# M2 Parser Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `coffee-review parse` turns all 9,440 saved review pages into two parsed Parquet datasets, roasted and green. Values are text, unknown labels are kept, problems are recorded as issues, and every run writes a report with coverage and value shapes.

**Architecture:**
- **Pure parsing** (`parsers/`): one page in, one record and its issues out, driven by a single alias table.
- **A storage boundary for the output:** a `ParsedStore` Protocol, a Parquet implementation and an in-memory fake, all held to one contract test.
- **A pipeline** that reads the raw store, parses each page, builds the report and writes everything.
- **A CLI command** that reuses M1's logging and progress bar.

**Tech Stack:** Python 3.14, selectolax (HTML), Polars (Parquet), pydantic, Rich, pytest, inline-snapshot, hypothesis.

**Spec:** `docs/superpowers/specs/2026-11-21-m2-parser-design.md` (approved). Parent: `docs/superpowers/specs/2026-11-20-pipeline-roadmap-design.md`.

## Global Constraints

- **Each task ends with a pause for Tyler's review.** Claude explains the change and commits only after Tyler has reviewed it. One concern per commit.
- **The dependency rule:** `cli → pipeline → {parsers, storage} → {models, config}`. `parsers/` imports no I/O, and only `storage/` knows paths and formats (ADR 0006).
- **Values stay text in M2.** Nothing is converted to numbers or dates here; that's M3.
- **A missing value is `None`.** Values are never guessed.
- **One bad page never stops a run.** It becomes a `ParseIssue`.
- **The site's `green-coffee-review` class decides the dataset.** For roasted pages, `sold_green` is true when the title has `Green` as a word after a dash (case-insensitive).
- **Fixtures keep the markup, labels and short values, but never review prose.** Section paragraphs are replaced with placeholder sentences.
- **Tests never touch the network or `data/`.**
- **Every task ends with `uv run pre-commit run --all-files` and `uv run pytest` passing.**

## Review Focus

1. **Text that's only whitespace or `&nbsp;`** (for example `<td> </td>`). It must become `None`, not `""` or `"\xa0"`. Test: `test_blank_and_nbsp_values_are_none` (Task 4).
2. **A label without its colon, or with extra spaces** (`Roast Level`, `Roast  Level :`). It must still match its alias. Test: `test_label_normalisation_variants` (Task 3).
3. **A sidebar `h2` placed before the review's last section.** Parsing must stop at the first ignored heading, so the sidebar's text never ends up in `bottom_line`. Test: `test_sections_stop_at_first_ignored_heading` (Task 4).
4. **A manifest row whose page file is missing** (`PageNotFoundError`). It must become an issue, `page_missing`, and the run must carry on. Test: `test_missing_page_file_is_an_issue` (Task 7).
5. **An earlier run's Parquet files.** A new run must replace them completely, with no leftover rows from deleted reviews. Test: `test_rewrite_replaces_previous_rows` (Task 5).

### Task 5: The parsed-data storage boundary

**Files:**
- Modify: `pyproject.toml` (`uv add polars`)
- Create: `src/coffee_review/storage/parsed_store.py`
- Modify: `tests/fakes.py` (add `InMemoryParsedStore`)
- Test: `tests/storage/test_parsed_store_contract.py`, `tests/storage/test_parquet_parsed_store.py`

**Interfaces:**
- **`class ParsedStore(Protocol)`:**
  - `write(records: Sequence[ParsedReview], issues: Sequence[ParseIssue], report_markdown: str) -> None` replaces everything from the previous run.
  - `read_reviews(dataset: Dataset) -> list[ParsedReview]` is for tests, and for M3 later.
  - `read_issues() -> list[ParseIssue]`
  - `report_location() -> str`: where the report can be read, for the CLI to print (`data/parsed/report.md` for Parquet; `"in memory"` for the fake)
  - `close() -> None`
- **`ParquetParsedStore(root: Path)`** writes, under `root`:
  - `roasted/reviews.parquet` and `roasted/extra_fields.parquet`
  - `green/reviews.parquet` and `green/extra_fields.parquet`
  - `parse_issues.parquet`
  - `report.md`

  **How it writes them:**
  - The column names and order are exactly as in the spec. Text columns are `pl.Utf8`, `delisted` and `sold_green` are `pl.Boolean`, and `extra_count` is `pl.Int32`.
  - Rows are sorted by slug, and the extra fields by slug and then label.
  - Each file is written to a temp path in its own folder and then moved into place, so a write that fails leaves no temp file behind.
  - Empty datasets are still written, with their schema and no rows.
- **`open_parsed_store(settings: Settings) -> ParsedStore`** returns `ParquetParsedStore(settings.data_dir / "parsed")`.
- **`InMemoryParsedStore`** keeps the last `write` call's arguments.

### Task 8: The parse pipeline

**Files:**
- Create: `src/coffee_review/pipeline/parse.py`
- Test: `tests/pipeline/test_parse.py`

**Interfaces:**
- Consumes: `RawStore`, `ParsedStore`, `parse_review_page`, Task 6, and `RunProgress` (Task 7).
- Produces:
  - **`run_parse(*, raw: RawStore, parsed: ParsedStore, progress: RunProgress | None = None, clock: Callable[[], float] = time.monotonic) -> ParseRunResult`.** It does the following:
    1. Calls `raw.load_manifest()`. Rows with `fetched_at is None` count as `skipped`.
    2. Calls `progress.start(len(rows))`.
    3. For each row, in slug order: `read_page`, then `parse_review_page(slug, url, html, delisted=delisted_at is not None)`. It collects the records and issues and advances progress with `record.dataset`, or `"issue"` when there's no record.
       - **`PageNotFoundError`** becomes the issue `page_missing`.
       - **Any other exception from parsing one page** becomes the issue `no_review_template`, with the detail `f"{type}: {msg}"`, so the run carries on.
    4. Calls `build_parse_report`, then `parsed.write(records, issues, render_report_markdown(...))`, then `progress.finish()` in a `finally`.
    5. Logs the summary line at INFO.
  - **`ParseRunResult`** has `report: ParseReport`, `elapsed_seconds: float` and `report_location: str` (from `parsed.report_location()`).
  - **`parse(settings: Settings, *, progress: RunProgress | None = None) -> ParseRunResult`** is the composition root: `open_raw_store` and `open_parsed_store`, both closed in a `finally`.

- [ ] **Step 1: Write failing tests**, using `InMemoryRawStore` seeded with fixture HTML and `InMemoryParsedStore`:
  - `test_parses_every_saved_page`

  - `test_failed_status_with_saved_copy_is_still_parsed`
